# Mate — repository review

**Status at 0.11.0 (2026-10-31).** This review is from 0.3.0 and is kept as
history. The status below was checked against the code with a search, not
by running each case. Line numbers in the text are those of 0.3.0.

- **Fixed:** M7 (a Content-Security-Policy in the built page), M8 (the
  address and token of another session are not shown), M9 (a replacement
  the reader typed is not written over by a new selection, and a removal
  stays one), and the MCP `serverInfo` version, which is the app's own now.
  M4 and M5 (a failed start of the door is not kept, and
  `mcp:bind` takes only a session made for the reader's own agent), H1 (paths from a session file are checked inside the context,
  and a backup name must be digits) and H2 (`.git/config` is watched, as the
  hooks are). Documentation items 2, 3 and 4 (Codex and "no shell", the test
  command, the number of configs) are corrected in the documents. M7 is half
  done: new windows are denied and navigation is guarded.
- **Not a fault in 0.11.0:** H3. The code counts with `range.toString()`,
  which is the text of the nodes and includes the hidden markup. The review
  feared `Selection.toString()`, which is the text as drawn. A test in
  `smoke.e2e.ts` now selects over markup and picks a repeated word, and it
  passes.
- **Still open, seen in the code:** M6 (the marker scanner does not know code
  fences). It is not a small fix: a comment on a passage inside a fenced
  block puts its marker inside the fence, so skipping fences would lose it.
  The marker would have to go after the closing fence, and the way a marker
  finds its passage would change with it.
- **Unclear:** the SSH `--` after the host. OpenSSH reads options again
  after the host, so it is probably fine, but it was not tried on a real
  host here. M2 shows no serialization of draft edits in `context.ts`, not
  confirmed by a test.
- **Not checked again:** M1, M3, the rest of the Low list, the test
  coverage list, and documentation items 1, 5, 6 and 7.

Date: 2026-10-12. Reviewed: the whole repository at commit working-tree state,
from four angles (security, main-process code quality, renderer/markdown
invariant, docs & tests). Verified locally: `pnpm test` 24/24 pass,
`pnpm typecheck` clean, `pnpm build` succeeds.

## Summary

The codebase is in good shape: the architecture rules are real and mostly
enforced in code, the write discipline (temp file + rename) is applied
uniformly, the MCP endpoint is genuinely hardened, and the test suite asserts
real behavior. Three issues stand above the rest and are worth fixing before
the next release:

1. **Session-file path poisoning** — a crafted `.sessions/**/session.json`
   turns the reader's Revert / "Approve this file" click into an arbitrary
   file write outside the context.
2. **`.git/config` is outside the guard** — an agent can plant git config
   that executes on the reader's later git commands.
3. **Comment selection is broken across markup** — the "page text equals
   file text" invariant holds in the piece tree but fails at the DOM
   selection layer, so comments spanning bold/italics/links or source
   newlines fail or anchor to the wrong occurrence.

## High

### H1 — Session-file poisoning: Revert / Approve writes attacker-controlled bytes to an attacker-controlled path

`guard.put` joins paths without any containment check
(`apps/desktop/src/main/guard.ts:71-76`). The paths it receives in the
revert/settle flows come from `session.json`, which lives inside the context
and is parsed with no validation (`sessions.ts:152`):

- `sessions.ts:494` — `readFile(path.join(contextDir, ...change.path.split('/')))`
- `sessions.ts:497-498` — backup read, then `put(contextDir, change.path, before)`
- `sessions.ts:518,524-525` — same pattern in `settleHeld`

A session file containing `changes: [{path: "../../../../Users/x/.zshrc",
backup: "0", ...}]` plus a `backups/0` payload makes the reader's Revert
click write outside the context. The UI (`Agent.tsx:160`) even presents held
entries as "The agent wants to change <path>", so the prompt looks
legitimate. Two routes to planting the file: a malicious context ships it;
or an invited agent rewrites `.sessions/**` during a turn — the guard
explicitly skips `.sessions` (`guard.ts:34`), so the tampering is never
detected. `change.backup` / `held.file` are also joined unchecked (arbitrary
relative read).

Fix: validate `change.path` / `held.path` with the same rule as `mcp.ts`'s
`partsOf` (no empty or dot-leading parts) inside `revertChange`,
`settleHeld`, and defensively in `judge` — or make `put` itself call
`resolveInside`. Require `backup` / `held.file` to match `/^\d+$/`.
Stop excluding `.sessions` from the guard snapshot (or at least snapshot
`session.json` files).

### H2 — `.git/config` is outside the guard

`guard.ts:33-34` skips all of `.git` and re-adds only `.git/hooks`
(`guard.ts:50`). But `.git/config` is just as dangerous: an agent with
Edit/Write tools can set `core.hooksPath` to a directory inside the context
(which it can also write), or `core.sshCommand`, `core.pager`, etc. The
change is never snapshotted or held, survives the turn, and fires the next
time the reader runs git in that repo — plausible, since reverting agent
damage is exactly when a reader reaches for git.

Fix: also snapshot `.git/config` (small, fixed name).

### H3 — Selection offsets are rendered-text offsets, not file offsets

`docs/architecture.md:116-120` claims "what the reader selects is a passage
of the file". It isn't true in Chromium:

- `styles.css:89` — `.syntax { display: none; }`. `Selection.toString()`
  serializes *rendered* text: `display:none` subtrees are excluded and
  CSS-collapsible whitespace is collapsed.
- `App.tsx:240-245` — `picked = range.toString().trim()` and
  `from = before.toString().length` therefore measure a text that differs
  from the file.

Three concrete failure modes:

1. Selecting across any inline markup fails outright: `**bold** and *em*`
   yields anchor `"bold and em"`, which `insertComment`
   (`shared/comments.ts:172-174`) cannot find → "That text is not in this
   document."
2. Selecting across an unwrapped source newline fails (file has `\n`, anchor
   gets a space) — works only when the line happens to wrap visually at
   exactly that point, i.e. layout-dependent.
3. Repeated passages anchor silently wrong: `from` undercounts by every
   hidden markup character, so `indexOf(anchor, from)` can match an earlier
   occurrence — misplaced comment, or a spurious "more than once on that
   line" error.

`tests/markdown.test.ts` cannot catch any of this: it validates the piece
tree in Node, where there is no DOM.

Fix: stop measuring the DOM string. Leaves partition the file contiguously,
so a DOM point maps exactly to a file offset (`leaf.from + offsetWithinLeaf`).
Put leaf offsets on the text nodes (e.g. `data-from` attributes in
`Rendered.tsx`), walk the selection's boundary containers in `pickPassage`,
and set `anchor = view.text.slice(from, to)`. As a side benefit, make the
offset computation a pure function so it is unit-testable in node:test.

## Medium

### M1 — Symlinks inside the context defeat containment and are invisible to the guard

`resolveInside` (`context.ts:52-57`) is a pure string check; nothing calls
`realpath`. The walkers in `guard.ts:41-42` and `contextIndex.ts:62` use
`entry.isFile()`, which is false for symlinks — so a symlink shipped inside
a context is never snapshotted or indexed, but reads and writes follow it:

- `readContextFile` (`context.ts:28`) and MCP `mate_read` (`mcp.ts:103`)
  read through a symlink: `shelf/notes.md -> ~/Documents/secret.md` lets an
  agent exfiltrate any readable file. (`mate_read` doesn't even require the
  `.md` suffix.)
- A judge-approved write to a symlinked path writes through the link
  (`guard.ts:75`); the guard sees no change and nothing is reverted.

Fix: `lstat` in `walk` / `listMarkdown` / `put` and reject or skip symlinks,
or `realpath` the target and re-check containment. (`editDraft`'s
temp+rename is safe — `rename` replaces the link itself.)

### M2 — Draft edits are unsynchronized read-modify-write (lost updates)

`context.ts:88-91` makes each write atomic but nothing serializes
read → modify → write. The MCP path serializes itself (`mcp.ts:171`) and
session messages are gated, but `comment:add` / `comment:reply` /
`comment:apply` / `comment:anchor` (`index.ts:153-178`) are not serialized
against each other, against the MCP queue, or across two windows on the same
context. Two overlapping edits silently drop one comment/reply, or compute
duplicate comment ids. Also, the temp file lands inside `draft/` while the
guard may be watching; a turn ending in the write→rename window would see it
as an agent-created file.

Fix: a per-file promise chain in `context.ts` (same pattern as `mcp.ts`'s
queue), shared by the IPC handlers and the MCP tool path.

### M3 — `end()` can reject unhandled and leave the context permanently busy

`sessions.ts:468,470,477` call `void end(...)`; the async body awaits
`proposed` / `changesSince` / `judge` with no surrounding catch. One concrete
trigger: `takeSnapshot` stats each file after walking (`guard.ts:53`) — a
file deleted between walk and stat throws out of `changesSince`. If that
happens before `release()`, the result is an unhandled rejection, `finished`
never settles, and `busy` / `turns` / `watching` are never cleared — every
later `sendMessage` fails with "Another agent is working in this context"
until restart.

Fix: wrap the `end` body in try/catch that always calls `release()`, saves,
emits, and settles (pushing a `mate` failure message like the existing catch
at `sessions.ts:462`).

### M4 — A failed MCP start bricks the door until restart

`index.ts:82` — `door ??= startMcp(...)`. If `startMcp` rejects (any listen
error other than the first EADDRINUSE fallback), `door` keeps the rejected
promise and every later `mcp:bind` re-throws the same stale rejection.

Fix: `door = startMcp(...); door.catch(() => { door = null })`.

### M5 — `mcp:bind` never checks the session exists or is an MCP session

`index.ts:182` binds whatever `(project, id)` the renderer sends. The
renderer only passes `agent === 'mcp'` sessions, but main shouldn't rely on
that: binding a live Claude session lets MCP tool calls mutate it through
`loadSession` (which returns the live turn session), and `callTool`'s
`finally` (`mcp.ts:186-193`) writes `running: false` over live state
mid-turn.

Fix: in the `mcp:bind` handler, `loadSession` and require
`session.agent === 'mcp'`.

### M6 — The comment-marker scanner is not markdown-aware

`scan` (`shared/comments.ts:26-53`) matches `<!-- @comment` anywhere,
including inside fenced code blocks and inline code. A *valid* marker shown
as documentation is parsed as a real comment and cut out of the visible text
by `strip`. Not hypothetical: `README.md:114` contains a valid example
marker inside a ```` ```markdown ```` fence — opened in Mate's read view,
that line vanishes from the page and becomes a phantom thread whose anchor
even resolves inside the same fence.

Fix: skip matches inside `FencedCode` / `InlineCode` / `CodeBlock`
(`@lezer/markdown` is already a dependency), or only treat alone-on-line
markers as Mate's own and document md-redline-style inline markers as
read-only.

### M7 — No CSP, no navigation or window-open guards

`index.ts:26-56` sets `sandbox/contextIsolation/nodeIntegration` correctly,
but there is no Content-Security-Policy in the renderer's `index.html`, no
`setWindowOpenHandler`, and no `will-navigate` handler. Today there is no
known XSS sink (everything is React text nodes), so this is defense in
depth — but the stakes of a single future injection are high: `window.mate`
exposes `bindMcp`, which returns the MCP bearer token.

Fix: add a CSP meta tag (`default-src 'self'; script-src 'self';
style-src 'self' 'unsafe-inline'; img-src 'none'; connect-src 'self'`),
deny all `window.open`, block navigation.

### M8 — `bindMcp` race shows the wrong door credentials

`Agent.tsx:54-57`: the effect has no stale-response guard. Switching
sessions quickly, an earlier `bindMcp` promise can resolve last, leaving
`door` showing the URL/token for a different session than the one actually
bound — the reader pastes credentials pointing at the wrong session. Every
other async effect in `App.tsx` uses the `let current = true` pattern; this
one should too.

### M9 — Re-selecting in Remove mode silently cancels the removal

`App.tsx:247`: `setSuggestion((current) => (current ? picked : current))`.
In Remove mode the suggestion is `''` — falsy — so selecting a new passage
while the composer is open replaces the removal; then `insertComment`
(`comments.ts:216`) drops a suggestion equal to the anchor, and the Remove
becomes a plain note or throws "The comment is empty."

Fix: track intent explicitly (`current === null ? picked : current`) rather
than using emptiness as the "untouched" signal.

## Low

- **SSH remote command is broken** (`agents.ts:202`): `--` is placed after
  the host, so the remote shell receives it as a command
  (`--: command not found` in sh/bash/zsh). `--` ends option parsing only
  *before* the host. The quoting itself is correct. Fix: drop the `--`.
  This path presumably has never worked end-to-end — worth a real-host test.
- **MCP `serverInfo` version stale** (`mcp.ts:215`): reports `0.2.0` while
  the app is 0.3.0. Read from `app.getVersion()`.
- **Guard restore writes not atomic** (`guard.ts:75`): plain `writeFile`; a
  crash mid-restore leaves a truncated file where the guard was putting the
  original back. Use the same temp+rename as `editDraft`. Related documented
  ceilings: files over 5 MB and `node_modules` under a context are unwatched.
- **`session:stop` not scoped to the caller's context** (`index.ts:197`):
  any window that learns a session UUID can kill another context's turn.
- **Session-save failures swallowed or misattributed** (`sessions.ts:452,463`
  `.catch(() => {})` loses the whole transcript on a read-only context;
  `sessions.ts:480` can reject `session:send` after the turn already
  started). Also: a message is lost when `begin` fails to start a turn
  (`sessions.ts:316,384-389`).
- **MCP oversize body hangs the client** (`mcp.ts:263`): `request.destroy()`
  sends no response; return 413 instead. Also no `request.on('error')`.
- **`anchorComment` passes a stale `from`** (`comments.ts:277-280`): the old
  marker is removed before `place`, but `from` was measured with it present;
  with repeated passages the re-anchor can land on the wrong occurrence.
- **CRLF frontmatter not detected** (`markdown.ts:74`): the regex is LF-only;
  intents/principles files with CRLF render the frontmatter as a horizontal
  rule plus setext heading. (Drafts are unaffected — `\r` is stripped on
  read.)
- **`entering` map grows forever** (`sessions.ts:255`); **`startSession`
  doesn't verify the project exists** (`sessions.ts:164-191` — a typo dies
  later with a misleading "Claude is not on this computer");
  **`listAgents` tests existence, not executability** (`agents.ts:225`);
  **`.tmp` litter after crashes** is never cleaned.
- **Agent send wipes text typed during the round-trip** (`Agent.tsx:81-84`).
- Cosmetic: stray visible newlines inside tables (delimiter-row `\n`
  gap-filled between `display: table-row` divs).
- `placeOf` classifies `projects/p/draft/sub/x.md` as `project`, not `draft`
  (`contextIndex.ts:50-51`) — inconsistent with `editDraft` if a draft folder
  ever gains a subdirectory.

## Documentation inaccuracies

1. **`pnpm-workspace.yaml` requires pnpm 11, docs say "pnpm 10 or newer".**
   The workspace file uses `allowBuilds:` (pnpm-workspace.yaml:4-6), a pnpm
   11 key; pnpm 10 used `onlyBuiltDependencies`. On pnpm 10 the key is
   unrecognized, the `electron`/`esbuild` postinstalls stay blocked, and
   `node_modules/electron/dist` is missing — exactly the failure
   `README.md:82-84` gives repair steps for. Contradicts `README.md:58`,
   `docs/mvp.md:46`, CONTRIBUTING.md, and `package.json` engines
   `"pnpm": ">=10"`. Either say pnpm 11+ or use the pnpm-10-compatible key.
2. **"No shell" is not true for Codex.** AGENTS.md rule 6 and
   `README.md:162` say agents get file tools and no shell. That holds for
   Claude (`--tools Read,Glob,Grep,Edit,Write`) and Hermes, but Codex runs
   with its default toolset under `--sandbox read-only|workspace-write`
   (`agents.ts:88-98`), and its command execution is even surfaced as a
   `shell` tool event (`agents.ts:106-107`). The sandbox bounds it, but the
   blanket claim overstates the guarantee.
3. **AGENTS.md test command omits the loader.** The table gives
   `node --experimental-strip-types --test tests/*.test.ts`; the real script
   adds `--import ./tests/register.mjs`.
4. **CONTRIBUTING.md says typecheck covers "all three configs"** — there are
   two (`tsconfig.node.json`, `tsconfig.web.json`); `tsconfig.json` is a
   references-only solution file. AGENTS.md's "both configs" is correct.
5. **architecture.md's process-split diagram is incomplete** — four bridge
   channels are missing: `listAgents`, `bindMcp`, `listSessions`, `stopTurn`.
6. **model.md overclaims md-redline compatibility** — only `replies` and
   `status` follow md-redline; `suggestion` is Mate's own (architecture.md
   states this correctly).
7. MCP `serverInfo` version 0.2.0 vs package 0.3.0 (also listed under Low).

Everything else checked was accurate: module descriptions, dependency
versions, engines, env vars, CHANGELOG 0.3.0 entries, roadmap "Built" items
1–5, README quick start.

## Test coverage

24 tests in 6 files, all passing; none vacuous — they assert bytes on disk
and session state. Good coverage of `comments.ts`, `contextIndex.ts`,
`agents.ts` (argv contracts, SSH quoting), guard diffing, `judge` both
directions via integration, MCP auth and tools, `assist.ts`, and the
tree-level character invariant.

Riskiest untested logic, prioritized:

1. **`readContextFile` validation** (`context.ts:23-30`) — the only path
   where the renderer names a file to read; its `.md`/dot-part guards have
   no test.
2. **`mateWrote` / guard interplay** (`guard.ts:22-27`) — a comment the
   reader adds mid-turn must not be reverted as agent damage.
3. **Session failure paths** (`sessions.ts:468-477`) — spawn failure,
   non-zero exit, auth-error detection, `stopTurn`.
4. **`judge` deletion branches** — `before: null` / `after: null` backup
   naming never exercised through a turn.
5. **MCP transport edges** — oversize body, batch arrays, unknown-method
   -32601, EADDRINUSE fallback.
6. **The selection layer** (H3) — currently untestable in node:test; the
   proposed pure offset-mapping function would fix that.
7. The markdown invariant test exercises only 5 documents; a table of ~30
   one-construct inputs would harden it against silent lezer behavior
   changes (the FencedCode/Escape/HardBreak branches rest on structural
   assumptions about the lezer tree).

## What is genuinely well done

- The sandbox configuration is exactly as claimed, the preload surface is
  typed with no generic `invoke`, and there is no
  `dangerouslySetInnerHTML`/`innerHTML`/`eval`/`<a>`/`<img>` anywhere —
  HTML, links, and images in drafts are truly inert.
- MCP hardening is real: loopback-only bind, length-checked
  `timingSafeEqual`, Origin rejection, 0600 token file, per-call
  serialization, and every write routed through `judge`. MCP cannot bypass
  `judge`.
- Agent CLIs are spawned with argument arrays (no shell), prompts go via
  stdin, and Claude's flags (`--strict-mcp-config`, `--setting-sources ''`,
  tool allowlist) match the stated policy. SSH host validation and quoting
  are correct.
- Temp-file + rename is applied uniformly (drafts, sessions, index), and
  session files persist `running: false` so a crash can't resurrect a
  phantom turn.
- `mateWrote` coordination between Mate's own writes and the guard snapshot
  is thought through and applied at every write site.
- The comment-marker scanner (not regex) handles `-->` inside strings via a
  retry loop, escapes `-->` on write, and preserves unknown fields.
- The piece-tree construction in `markdown.ts` verifiably tiles
  `[0, text.length)` exactly once for ~40 tricky inputs (setext, tables,
  autolinks, entities, hard breaks, nested emphasis, CRLF, frontmatter,
  unclosed fences, escapes at EOF).
- Error messages are written for the reader, and the `ponytail:` comments
  checked are all still accurate.

## Suggested order of work

1. H1 (validate session paths; guard `.sessions`) and H2 (snapshot
   `.git/config`) — both reachable by an invited agent using only its
   granted tools.
2. H3 (offset-based selection mapping) — the core reader interaction is
   broken across markup today.
3. M1 (symlinks) and M2 (serialize `editDraft`) — containment and
   data-loss fixes in the same files.
4. M3–M5 (session/MCP state robustness), M6 (marker scanner vs code
   fences).
5. M7 (CSP/navigation), M8–M9 (UI races), then the Low list and doc fixes
   (pnpm 11 note, Codex "no shell" wording).
